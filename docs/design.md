# 沿海城市潮汐防洪推演系统 · 技术方案

## 1. 需求拆解

| 业务能力 | 关键技术点 |
| --- | --- |
| 五要素同屏(降雨/潮位/河道水位/泵站负荷/闸门状态) | 统一时间步的状态帧 + 时间轴 scrub |
| 拖动时间轴看积水形成与消退 | 整程预计算的帧序列, 街区积水深曲面按帧着色 |
| 运行中调闸门开度/泵站组合/分洪顺序 | 调度指令即数据(带时间戳的 Controls), 改后整程增量重算 |
| 每次调整重新预测各街区淹没深度与到达时间 | 独立副本仿真, 不污染主画布; 输出峰值/到达/峰现 |
| 倒灌/过载/上下游冲突解释原因 | 规则引擎诊断, 给出可读成因 + 定位时步 |
| 提供可执行替代组合 | 基于诊断类型自动生成 A/B/C 组合并仿真评分 |
| 多套方案同步回放比较 | 统一时间轴对齐多方案帧, 指标表 + 差值渲染 |
| 意外断开恢复未结束推演 | 事件溯源快照(状态+指令+已发事件), JSON 原子落盘 |

## 2. 总体架构

```
前端(地图/时间轴/调度面板)
   │  WebSocket: 指令(Controls patch) / 订阅(帧流、诊断、方案)
   ▼
推演服务(本仓库 floodsim 为参考内核)
  ├─ model      水网拓扑: 水体/闸/泵站/街区/降雨/潮位/联锁
  ├─ engine     5min 步进求解: 堰流/倒流/泵站/质量平衡/联锁/分洪顺序
  ├─ rules      诊断(倒灌/过载/冲突) + 替代组合生成与评分
  ├─ scenario   多方案生命周期、同步帧对齐、时间轴导出
  └─ session    快照原子写盘与恢复
   │
   ▼
PostgreSQL/PostGIS(拓扑与预案) + Redis(会话/帧缓存) + 对象存储(快照)
```

生产环境水动力建议替换为成熟一维河网+二维地表模型(如 SWMM/InfoWorks ICM/
自研有限体积模型), 本内核用宽顶堰+节点水量平衡表达相同的输入输出契约,
便于先贯通交互与调度闭环, 再替换求解器。

## 3. 数据模型(`floodsim/model.py`)

- `WaterBody`: 河道/蓄滞洪区/虚拟海。体积经 stage-volume 表换算水位;
  `is_sea` 为潮位边界, 不参与质量平衡。
- `Gate`: src→dst 有向连接, 分四类:
  `tide`(挡潮闸)、`diversion`(分洪闸)、`block`(街区拍门, 仅正向)、`plain`。
  流量用宽顶堰公式, 淹没流按 Villemonte 折减; 反向流量带负号即"倒灌"。
- `PumpStation`: 单机容量 × 开启台数 + 可增援移动泵车;
  负荷率 = 实际抽排 / (固定+移动)总容量。
- `Block`: 汇水街区, 水深=积水体积/面积, 拍门自排受潮水位顶托自动截止。
- `Rainfall`: 统一雨型, 每街区可设折减/扣损(如商业区硬化、低洼区)。
- `Interlock`: 潮位阈值 → 应关闭挡潮闸。联锁只产生"应关"告警,
  人工 `forced_close` 预案才物理关闭 —— 这样"指令与联锁冲突"和"真倒灌"
  都能被观测到, 而不是被系统静默纠正。

## 4. 时间步进与增量重算(`floodsim/engine.py`)

每步:
1. 取潮位、上游来水、降雨边界;
2. 应用截至当前时刻的人工指令(闸开度、泵组合);
3. 计算挡潮联锁告警与强制关闭、按分洪顺序自动开闸(下游优先判据);
4. 计算各闸过流与泵站抽排;
5. 节点质量平衡, 水量不足时迭代按比例缩减出流(守恒), 更新水位/水深;
6. 记录 `StepRecord`, 检测连续段去重的倒灌/过载事件与街区到达时间。

### 4.1 调度即数据, 支持"改一处、重预测"
`Controls` 只有四类纯数据:
- `gate_actions: [(time, gate_id, opening)]`
- `pump_actions: [(time, station_id, on_units, mobile_on)]`
- `diversion_order: [gate_id,…]` 分洪优先级
- `forced_close: [gate_id,…]` 硬联锁预案

用户在 t=02:10 拖动闸门或勾选泵组, 只是向 Controls 追加一条指令,
随后 `Scenario.apply_controls()` 用深拷贝拓扑整程重跑(12h × 5min = 144 步,
纯 Python 单核约 30~60ms), 立即返回新的峰值/到达时间。
生产环境的优化路径:
- 指令 t 之前的状态对"同拓扑同边界"是可复用的检查点, 可从最近检查点续算;
- 多方案并行用进程池;
- 重模型按子流域分区做增量/并行重算。

## 5. 时间轴交互与五要素呈现

- 推演整程产出帧序列(`scenario.export_timeline`), 每帧含:
  各水体水位、各街区水深、各闸开度/流量/联锁告警、各站流量/负荷。
- 前端时间轴 scrub 只读帧缓存, O(1) 定位; 地图上街区面按水深
  蓝—青—黄—红分级, 河道按水位色带, 闸/泵用状态图标(开/关/告警/过载),
  潮位与降雨做背景曲线并叠加当前游标。
- "积水形成与消退"由水深曲线直接体现; 到达时间 = 水深首次越过 0.15m,
  峰现时间与退水时间同步标注。

## 6. 诊断与替代组合(`floodsim/rules.py`)

`analyze(city, controls)` 在独立副本上重跑, 输出 `Finding` 列表,
每条含类型、等级、对象、时步、**成因**与**可执行建议**:

1. **海水倒灌(backflow, danger)**: 挡潮闸在潮位超过联锁阈值时仍为负流量。
   成因示例: "下游水位 2.05m 高于上游且闸门未关闭"。
2. **设备过载(overload, warning)**: 固定机组与移动泵车叠加超过额定能力。
   连续过载只报一次(开始事件), 避免告警风暴。
3. **上下游冲突(conflict)**:
   - 人工开闸指令与挡潮联锁阈值冲突(指令若执行必倒灌);
   - 分洪闸已开启但下游水位顶托、下泄能力被淹没流压制(应先下游后上游);
   - 分洪顺序引用了不存在的闸(结构性错误, 未运行即可判)。

### 6.1 替代组合生成
按诊断命中类型装配候选, 每个候选**本身就是一份 Controls, 可一键下发**:
- **A 挡潮强排**: 挡潮闸纳入 `forced_close`; 全部固定机组潮前 30min 启泵
  预排; 移动泵车延后 30min 错峰, 避免叠加过载。
- **B 先下后上分洪**: 用"离海 BFS 距离"对分洪闸排序, 下游通道与蓄滞洪区
  先开, 预降水位后再放上游, 消除顶托。
- **C 组合方案**: A+B 同时生效。

每个候选立即仿真并按风险分排序:
`score = 100·Σ超警水深 + 500·挡潮倒灌步数 + 20·max(0, 最高负荷−100%)`,
分数最低者为推荐。系统还会如实指出"某种调整无收益"及其原因
(例如残余积水由顶托造成时, 加泵边际收益为零, 应改用蓄滞洪区腾库)。

## 7. 多方案同步回放比较(`floodsim/scenario.py`)

- `Scenario` 持有各自独立的 City 副本与 Controls, 互不影响;
  支持方案另存为、改参重算、回到任一历史版本。
- `compare([s1, s2,…], times)` 以公共时间轴对齐取帧,
  输出同步帧矩阵 + 每方案指标(峰值水深、到达时间、最大负荷、倒灌次数)。
- UI 建议: 地图支持分屏/叠放(透明度滑杆对比两方案积水范围),
  指标列做差值着色, 时间轴游标全局联动。

## 8. 断点续演(`floodsim/session.py`)

- 快照内容: 当前步 k/时刻 t、各水体水位与体积、各街区水深、各闸开度、
  已发生事件、到达时间统计, 外加完整 Controls(指令日志)。
- 触发时机: 每 N 步、每次人工调整后、以及页面 `visibilitychange` 隐藏时;
  写盘采用临时文件 + `os.replace` 原子替换, 避免半截文件。
- 恢复: 用静态拓扑工厂重建 City(拓扑不进快照, 避免漂移),
  灌入快照状态后从断点继续 `run()`; 未跑完的部分自动补算, 已发事件不重复。
- 生产环境可升级为: 快照写 Redis/对象存储 + 版本号,
  服务端按 session 做事件溯源; 多端同时打开同一推演时以服务端权威状态为准。

## 9. 工程化落地要点

- **实时性**: 参考内核 12h 推演 <0.1s, 足以支撑"拖动即重算"的交互节奏;
  接重模型时用 WebSocket 推送"先返回快速代理结果, 再用精细结果修正"。
- **标定与可信**: 堰流系数、泵站曲线、stage-volume 表、产汇流参数需用
  历史场次标定; UI 对模型结果标注置信度与数据更新时间。
- **安全约束**: 泵站最小启停间隔、闸门启闭速率、设备故障态、
  蓄滞洪区启用淹没损失应作为硬约束进入候选筛选, 而不仅是事后扣分。
- **权限与留痕**: 每条人工指令记录操作人/时间/依据, 预案下发需二次确认;
  联锁越权操作触发强制告警并可配置为禁止。
- **可观测**: 倒灌/过载/冲突事件进入告警中心, 与实际 SCADA 比对做滚动修正。

## 10. 参考实现验证

`python3 demo.py` 端到端演示: 错误调度 → 三类风险诊断与成因 →
三套可执行替代组合及评分 → 双方案同步回放 → 无效调整的解释 →
推演 3h20m 处"断线"后从快照恢复并跑完。

`python3 -m unittest discover -s tests` 共 9 个用例, 覆盖:
倒灌检测、联锁告警与强制关闭、积水形成消退、质量守恒、
三类诊断、替代组合可执行且更优、多方案比较、改参重算、断点恢复。
